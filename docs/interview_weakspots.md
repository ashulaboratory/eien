## A. Go 言語の頻出質問

### A-1. Go の特徴を3つ挙げてください。

> (1) 静的型付け + コンパイル言語、(2) goroutine による軽量な並行処理、(3) 標準ライブラリが充実していて Web サーバが書ける。

### A-2. goroutine って何？

> Go のランタイムが管理する軽量スレッドです。OS スレッドが数MBのスタックを持つのに対し、goroutine は数KBから始まり必要に応じて伸びるので、何万個でも作れます。`go func() { ... }()` で起動するだけ。
> 並行処理に使い、複数 goroutine 間のやりとりは **チャネル**（`chan`）で行う、というのが Go の流儀です。
>
> **Eien で使ってる？** → 「直接書いた箇所は少ないですが、Echo が裏でリクエストごとに goroutine を立てています。cron ジョブも内部で goroutine 動作です」

### A-3. interface とは？

> 「メソッドの集まり」を型として定義する仕組み。**実装側で `implements` を宣言する必要がなく**、メソッドを満たせば自動的に実装したことになります（構造的型付け・ダックタイピング）。
> Eien では `ImageStore` インターフェースを切って、ローカル保存／クラウド保存を差し替え可能にしています。

### A-4. ポインタとは？

> 変数のメモリアドレスを指す型。`*User` は User へのポインタ、`&user` でアドレスを取る、`*p` で参照先の値を取り出す。
> Go では、(a) 関数に大きな構造体をコピーせず渡したい時、(b) 関数内で構造体を書き換えたい時、(c) nil を取り得る値を表現したい時、にポインタを使います。

### A-5. defer って何？

> 関数が終了する直前に実行される処理を予約する仕組み。
> `defer file.Close()` と書けば、関数を抜ける時に必ず Close される。エラーで途中 return しても呼ばれるので、**リソース解放の漏れを防げる**のが利点。
> Eien では DB プールの `defer pool.Close()`、cron の `defer scheduler.Stop()` で使っています。

### A-6. Go のエラーハンドリングについて。

> Go は例外がなく、エラーは **戻り値**として返します。慣用句は：
>
> ```go
> result, err := doSomething()
> if err != nil {
>     return fmt.Errorf("doSomething: %w", err)
> }
> ```
>
> `%w` で**エラーをラップ**して原因を保持しつつ文脈を足せます。受け手は `errors.Is(err, target)` でラップを辿って判定可能。

### A-7. context.Context って何？

> リクエストやジョブの「**実行コンテキスト**」を表す型。**キャンセル**、**タイムアウト**、**値の受け渡し**の3つの機能を持ちます。
> Eien では認証ミドルウェアが `context.WithValue(ctx, userIDKey, userID)` で `userID` を入れ、ハンドラが `auth.UserIDFromContext(ctx)` で取り出す、という形で使っています。
> DB のクエリにも `context` を必ず渡すことで、HTTP リクエストがキャンセルされたら SQL もキャンセルされるようになっています。

## B. SQL / DB の頻出質問

### B-1. JOIN を説明してください。

> 複数テーブルを関連カラムで結合してデータを取るクエリ。
> - `INNER JOIN`：両側にデータがある行だけ
> - `LEFT JOIN`：左側は全部残し、右側になければ NULL
> - `RIGHT JOIN`：その逆
>
> Eien では、タイムライン取得で「posts と users を JOIN して投稿者名を一緒に取る」ような使い方をしています。

### B-2. 主キーと外部キーの違いは？

> **主キー**は、そのテーブル内で行を一意に識別する列。NOT NULL かつ UNIQUE。Eien の `users.id` (UUID) など。
> **外部キー**は、別テーブルの主キーを参照する列。整合性を DB に保証させる。Eien の `posts.group_id` は `groups.id` を参照。

### B-3. 正規化って何？

> データの重複と不整合を減らすためにテーブルを分割する設計手法。
> Eien の例：「ユーザー」と「グループ」と「所属関係」を1つの表に混ぜず、`users` / `groups` / `group_members` の3表に分けるのが第3正規形までの考え方。

### B-4. ACID とは？

> トランザクションが満たすべき4性質。
> - **A**tomicity（原子性）：全部実行 or 全部なかったことに
> - **C**onsistency（一貫性）：制約違反を許さない
> - **I**solation（独立性）：同時実行しても結果が単独実行と同等
> - **D**urability（永続性）：コミットしたら消えない

### B-5. PostgreSQL のトランザクション分離レベルって聞いたことある？

> 聞かれたら：「Read Committed（デフォルト）と Repeatable Read、Serializable があるのは知っています。Eien では特に変更せずデフォルトの Read Committed で動かしています」程度で OK。深掘りされたら正直に「現場で使い分ける経験はまだ無いです」。

### B-6. インデックスは具体的にどう動く？

> 多くの DB は **B-Tree**（バランス木）でインデックスを実装します。データを並べた木構造を別に持っておくことで、`O(N)` の全件スキャンが `O(log N)` の二分探索になる、というイメージです。
> Eien の `posts(group_id, created_at DESC)` インデックスなら、`group_id` で枝を選び、その先で `created_at` 降順にすでに並んでいるので、最新N件を取るのが非常に速い。

### B-7. EXPLAIN 使ったことある？

> ある or ない、正直に。「使ったことはまだ少ないですが、実行計画を出して seq scan が出てないか確認するツールという理解です」で十分。

## C. ネットワーク / Web 基礎

### C-1. HTTP と HTTPS の違いは？

> HTTPS は HTTP の通信を **TLS** で暗号化したもの。盗聴・改ざん・なりすましを防げます。サーバが証明書（公開鍵）を提示し、クライアントが認証局のチェーンで検証する仕組み。
> Eien は本番で Fly.io が自動で Let's Encrypt 証明書を発行してくれるので、`force_https = true` を設定するだけで HTTPS 強制になっています。

### C-2. Cookie とセッションの関係は？

> Cookie は **ブラウザがサーバから受け取って保存し、次回以降のリクエストに自動で付ける小さなデータ**。セッションは「**サーバ側で各ユーザーの状態を覚えておく仕組み**」。
> Eien は「サーバ側 sessions テーブルに状態を持ち、その ID を Cookie でブラウザに渡す」典型的なセッション方式です。

### C-3. CORS って何？

> Cross-Origin Resource Sharing。「**違うオリジン（プロトコル＋ドメイン＋ポートのセット）への JavaScript からのリクエストは、ブラウザがデフォルトでブロックする**」というセキュリティ仕様。サーバ側が `Access-Control-Allow-Origin` ヘッダで「このオリジンからは許す」と返して初めて通信できます。
> Eien では開発時 `localhost:5173`（Vite）と `localhost:8080`（Go）でオリジンが違うので、Echo の CORS ミドルウェアで明示的に許可しています。本番は同一オリジン配信なので CORS 不要。

### C-4. RESTful と GraphQL の違いは？

> REST は **リソース指向 + HTTPメソッド**。GraphQL は **1エンドポイント + クエリ言語でクライアントが必要なフィールドだけ取る**。
> Eien は MVP なので REST を選びました。GraphQL は型の恩恵が大きいですが、Eien 規模ではオーバースペックで、サーバ側の N+1 制御も別途必要になります。

### C-5. WebSocket とは？

> HTTP のように「リクエスト → レスポンス」で終わらず、**接続を張りっぱなしにして双方向に通信できる**プロトコル。チャット、リアルタイム通知、株価表示などに使います。
> Eien では Phase 1 のグループチャットで導入予定です。

## D. インフラ / デプロイ

### D-1. Docker と仮想マシンの違いは？

> 仮想マシン（VM）は OS ごと仮想化する。Docker は **OS カーネルを共有してプロセスだけ隔離する**（コンテナ）ので、起動が速く、リソース消費が小さい。
> Eien では Postgres と Mailhog をコンテナで開発時に立て、本番では Go バイナリをコンテナにして Fly.io にデプロイしています。

### D-2. CI と CD の違いは？

> **CI（Continuous Integration）**：コードを頻繁にマージし、自動でビルド・テストを走らせる。
> **CD（Continuous Delivery / Deployment）**：マージされた変更を自動でデプロイする仕組み。
> Eien は GitHub Actions で PR時に lint + build を回し、main マージで Fly.io デプロイをトリガーする構成です。

### D-3. マイグレーションって何？

> DB スキーマ変更を **バージョン管理する**仕組み。`000001_create_users.up.sql` で適用、`000001_create_users.down.sql` で取り消し、というように番号付きで管理します。
> Eien は `golang-migrate` を使い、サーバ起動時に `db/migrations` を見て未適用分を自動適用する流れです。複数サーバを同時起動する場合は競合し得るので、本番では1台ずつ立ち上げるか、別途マイグレーション専用ステップを CI に切る必要があります。

### D-4. ロードバランサって何？

> 複数のサーバにリクエストを振り分ける装置。Fly.io は内部で勝手にやってくれます。
> ステートレスなサーバなら何台にでも増やせますが、Eien はセッションを DB に持っているので、何台に増えてもユーザーから見て同じ状態が見えます。

### D-5. 監視・ログはどうしている？

正直モード。
> 今は `log.Printf` で標準出力に吐いているだけで、Fly.io の Web ダッシュボードから見られる程度です。本番運用するなら、**構造化ログ**（`slog`）に切り替えて、Grafana Loki や Datadog のような**ログ収集基盤**に流したいです。エラー通知は Sentry を入れたい。

## E. テスト

### E-1. テスト書いてる？

正直に。
> 現状は最小限です。Go の `testing` パッケージで一部のユーティリティ関数だけテストを書いています。
> 本来は (1) handler のテーブル駆動テスト、(2) repository は `testcontainers` で本物の Postgres を立てて統合テスト、(3) フロントは React Testing Library + Vitest、と組みたいですが、MVP 優先で後回しになっています。
> 「テストが書ける状態の設計」（依存性注入、インターフェース化）にはなっているので、追加コストは低いと思います。

### E-2. テーブル駆動テストって？

> Go でよくある書き方。入力と期待値の組を配列で並べ、ループで `t.Run` を回す形式。
>
> ```go
> tests := []struct {
>     name  string
>     input string
>     want  bool
> }{
>     {"valid email", "a@b.com", true},
>     {"no @", "abc", false},
> }
> for _, tt := range tests {
>     t.Run(tt.name, func(t *testing.T) {
>         if got := isValidEmail(tt.input); got != tt.want {
>             t.Errorf("got %v, want %v", got, tt.want)
>         }
>     })
> }
> ```
