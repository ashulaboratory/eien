# Eien セキュリティチェックリスト

> パブリックGitHubリポジトリで開発するため、機密情報の漏洩・クラウドコスト事故を絶対に防ぐためのルール。
> **このチェックリストは設計フェーズ・実装フェーズの全期間で参照する。**

---

## 1. リポジトリ運用ルール（必須）

- [ ] `.gitignore` に以下を最初に追加する：
  - `.env`
  - `.env.local`
  - `.env.production`
  - `*.pem`、`*.key`
  - `.vscode/`、`.idea/`
  - `node_modules/`、`vendor/`
- [ ] `.env.example` をリポジトリに含める（変数名のテンプレート、値はダミー）
- [ ] `README.md` のセットアップ手順は `.env.example` をコピーする形式で書く
- [ ] **直接的な秘密情報のコミット禁止**：APIキー、DBパスワード、JWT secret、SMTPパスワードなど
- [ ] **画像のメタデータ（EXIF）から場所情報を消す処理**を投稿時に入れる（プライバシー）

## 2. コミット前の自動チェック

- [ ] `gitleaks` を pre-commit フック（lefthook または husky）で実行
- [ ] GitHub Actions に `gitleaks` を追加（PRマージ前にも検出）
- [ ] Dependabot を有効化（依存ライブラリの脆弱性自動検知・PR）
- [ ] GitHub Code Scanning（CodeQL）を有効化

## 3. 環境変数管理

- [ ] ローカル開発：`.env` ファイル（gitignore対象）
- [ ] CI/CD：GitHub Secrets で管理
- [ ] 本番：Fly.io の `fly secrets set` で管理（CLIから設定、ファイルにしない）
- [ ] 環境変数の一覧を `docs/env_variables.md` などにドキュメント化（値は書かず、変数名と用途のみ）

## 4. クラウドコスト事故対策（最重要）

> 過去事例：誤って公開されたAWSアクセスキーが悪用され、数十万円〜数百万円の請求が発生するケースが頻発。

- [ ] AWS / Cloudflare のアクセスキーは絶対にコードに書かない
- [ ] アクセスキーは**最小権限のIAMユーザー**で発行（rootキーは絶対使わない）
- [ ] AWS：請求アラート設定（月$10など低めに）
- [ ] AWS：MFA有効化
- [ ] Cloudflare R2：APIトークンは特定バケットのみアクセス可に絞る
- [ ] **万一漏洩したらすぐにキー失効・rotate**：時間との勝負

## 5. アプリケーション層のセキュリティ

### 認証・セッション

- [ ] パスワードは bcrypt でハッシュ化（cost 10以上）
- [ ] セッションCookie：`HttpOnly`、`Secure`、`SameSite=Lax` 属性必須
- [ ] セッションIDは推測困難（CSPRNG使用、最低128bit）
- [ ] ログイン試行のレート制限（同IPから連続失敗は遅延 or 拒否）
- [ ] パスワードリセットのトークンは短時間で失効

### 入出力

- [ ] CSRF対策：状態変更操作にCSRFトークン検証
- [ ] XSS対策：Reactの自動エスケープに頼る（`dangerouslySetInnerHTML` を避ける）
- [ ] CSP（Content Security Policy）ヘッダ設定
- [ ] SQLインジェクション対策：sqlc使用で原則回避（生SQLを書く際もプレースホルダ徹底）
- [ ] ファイルアップロード：拡張子・MIMEタイプ・サイズ検証

### 認可

- [ ] 全API：「ログイン済み」だけでなく「そのデータへのアクセス権があるか」を必ず検証
- [ ] グループ別データへのアクセスは、必ずユーザーが所属するグループかをチェック
- [ ] 「自分の投稿」しか削除できないなどの所有権チェック

### 通信

- [ ] HTTPS必須（Fly.io標準で対応）
- [ ] HTTPはHTTPSに自動リダイレクト
- [ ] HSTS ヘッダ設定

## 6. パブリック公開前チェック

リポジトリをパブリックにする前に、必ず以下を確認：

- [ ] `git log --all -p | grep -iE "(api[_-]?key|secret|password|token)"` で過去コミット内に機密情報がないか確認
- [ ] 過去コミットに混入している場合は `git filter-repo` などで履歴から消去
- [ ] `gitleaks detect --no-git --source .` で全ファイルスキャン
- [ ] `.env.example` の中身に本物の値が入っていないか目視確認
- [ ] スクリーンショット・ドキュメント中に内部URLや本物のメールアドレス等が映っていないか

## 7. 公開後の継続運用

- [ ] Dependabot の更新PRを定期的にマージ
- [ ] Sentry のアラート確認（怪しいエラーが急増していないか）
- [ ] AWS / Cloudflare 月額請求の確認
- [ ] 不審なアクセスログ確認（メール送信の急増、認証失敗の急増など）
